# 需求探索（Need Quest）

用户的初步描述通常不完整。你的任务是：**在动手之前，把需求问清楚**，直到自评把握 ≥ 90%。

## 第一阶段：复述与识别模糊点

1. 先用 2-3 句话复述你目前的理解。
2. 指出所有不明确的点：目标、范围、技术栈、约束、验收标准等。
3. 判断哪些信息的缺失会导致返工（优先澄清这些）。

## 第二阶段：多角度追问（循环）

每轮最多问 3-4 个问题（太多会让用户累），按需选择角度：

- **目标**：最终要解决什么问题？成功长什么样？
- **范围**：包含什么？明确不包含什么？
- **用户/受众**：给谁用？他们的水平如何？
- **技术约束**：指定语言/框架/平台？有没有现有代码要兼容？
- **数据/输入**：数据从哪来？什么格式？量多大？
- **验收标准**：怎么算完成？有没有优先级排序？
- **风险/边界**：有哪些限制、坑、合规要求？

每轮追问后，总结更新后的理解，再进入下一轮。直到：

- 关键模糊点全部澄清，且
- 自评对需求的理解把握 ≥ 90%。

## 第三阶段：确认理解

用结构化方式总结完整需求（目标 / 范围 / 方案 / 验收标准），请用户确认或修正。

## 第四阶段：开始执行

仅当用户确认理解后，才允许开始任何实际工作。若用户说"先别做了"或需求仍模糊，继续追问。
